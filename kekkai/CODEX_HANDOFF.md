# KEKKAI 修正の引き継ぎ

確認日: 2026-10-26 UTC。作業ブランチ: `codex/live-monitor-review`。
基点: Claudeの最終追加修正 `79e268356534f7659cafd800d786ac37745d5164`。
GitHub: [PR #2](https://github.com/YSK3000/ysk/pull/2)。最新の検証状況はPRのCIを参照。

## 依頼に対する変更

- 実際の収集状態をAPI・画面・レポートに表示。初回収集、収集失敗、更新停止、ネットワーク未接続、停止を区別する。
- Macの収集コマンドが失敗したときはエラーとして扱う。主要な収集に失敗したサイクルでは、前回の通信記録・学習基準・成功時刻を更新しない。復旧後は自動で再開する。
- イベント接続が生きていても、5秒間隔で状態を確認する。ブラウザ側でも記録の古さを判定し、正常表示を続けない。
- 新規の未対応警告がないことを「安全」と断定しない。自宅の座標が不明なときは、架空の位置を地図に描かない。
- 概要画面に防御機能の稼働状況を追加。通信収集・脅威リストの更新・センサーの生存信号・Nmapの利用可否・外部ファイアウォールとの役割分担を表示する。インストール済みを稼働中とは扱わない。
- Macの署名情報は最大2件ずつバックグラウンドで取得し、通信の定期収集を待たせない。`serve` の二重起動を防止する。
- AIの `auto` はローカルのみ。明示的な `anthropic` 選択なしにクラウドへ送らない。ローカルAIの通信先をループバックへ制限し、プロキシ・リダイレクトを拒否する。
- Claudeのセンサー例外処理修正を統合。空の自動起動項目一覧も保存して古い項目を残さない。センサー削除時は無関係なファイル・リンクを残す。

## 併せて変わる点

- API `/api/coverage` とMCP `kekkai_coverage` を追加。MCP側でも収集失敗時の診断情報を取得できる。
- 新規警告なしの内部ラベルは `SECURE` から `NO ALERTS` へ変更。
- Linux検証環境でインターフェース列挙が制限される場合、sysfsで列挙を試みる。
- GET APIの待ち時間を制限。狭い画面では上部のネットワーク詳細を省略し、収集状態を読めるようにする。
- CIに画面の状態判定テストと実ソケット→PID→APIの検証を追加。Torの確認はコマンド終了コード・HTTP 2xx・空でないテキストを検証し、失敗がパイプで隠れないよう修正。6種類の成功・失敗応答で検証。
- 通信遮断機能、常駐エージェントの新規導入、ユーザーのMac設定の変更は行っていない。

## 確認したこと

- Pythonテスト138件中136件成功・2件スキップ。画面の状態判定7件成功。実OSのループバック接続からPID・継続収集・認証付きAPIまで成功。
- ブラウザで8画面を操作。地図データの読み込みと、座標不明時に自宅を描かないことを確認。
- ブラウザ内のテスト入力で、実監視・更新停止・収集エラー時に上部表示とゲージが一致することを確認。製品へのデモ機能追加ではない。
- デスクトップ幅1440px・スマートフォン幅390pxで確認。横スクロールのはみ出し、JavaScriptの未処理例外なし。
- 変更したPythonの3.9構文互換性とJavaScript構文を確認。
- 変更対象の秘密鍵・主要なアクセストークン形式・個人作業パス・共有ファイルIDをパターン検査し、該当なし。検査で全種類の機密情報を保証するものではない。
- 基点のClaude最終版は[GitHub Actionsの全ジョブ成功](https://github.com/YSK3000/ysk/actions/runs/40358682264)を確認。これはこのブランチの追加変更に対する結果ではない。

再実行するコマンド（`kekkai` ディレクトリ内）:

```sh
python3 -m unittest discover -s tests
node tests/test_health_ui.mjs
python3 scripts/verify_live_local.py
```

最後のスクリプトは一時データとループバックTCP接続だけを使う。LANスキャンや外部AI呼び出しは行わない。
Linuxコンテナでは、ソケットの取得に成功しても物理LANの情報が取得できず `offline` と報告される場合がある。
