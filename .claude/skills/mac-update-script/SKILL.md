# /mac-update-script

変更の要約: $ARGUMENTS

同じフォルダの `template.sh` をひな形にする（bash 3.2・BSD版コマンドで動作確認済みの作り）。

## 手順
1. **中身を決める**：変更するファイルの完全な新しい中身を用意する。差分ではなく、ファイル全体を置き換える形にする。
2. **ひな形を埋める**：
   - `__SCRIPT_NAME__`：`<アプリ名>-update-<YYYY-MM-DD>-<連番>.sh`（既存の名前の付け方があればそれに合わせる）
   - `__SUMMARY__`、`__APP_NAME__`、`__TARGET_DIR__`（例：`$HOME/Desktop/<プロジェクト名>`）
   - `# __PRECHECKS__`：対象が想定どおりの状態か確かめる条件（必要なファイルがあるか等）
   - `# __PUT_FILES__`：ファイルごとに `put_file "<相対パス>" "<SHA-256>"` とヒアドキュメントを並べる
     - SHA-256 は**埋め込む中身そのもの**から計算する（ヒアドキュメントは末尾に改行が付く）
     - 末尾に改行のないファイルやバイナリは base64 で埋め込む（ひな形のコメント参照）
     - 区切り文字（`__EOF_1__` など）はファイルの中身に出てこないものを使う
   - `# __BUILD__`：ビルドや確認のコマンド（任意）
3. **自分で試す**：`bash -n` で文法を確かめ、ダミーのフォルダに対して `DRY_RUN=1` → 本番 → 再実行（変更なしになること）→ `rollback.sh` の順に動かす。Linux で試した場合は、macOS で違いが出うる点がないか見直す。
4. **点検**：`/change-check` の手順で `scope-guardian`（頼まれたこと／それ以外）と `security-auditor`（危険なコマンド・秘密情報）を通す。
5. **渡す**：スクリプト全体の SHA-256 を計算し、ユーザーには次の1行を渡す（ハッシュが合わなければ実行されない）：
   ```
   echo "<SHA-256>  $HOME/Downloads/<ファイル名>" | shasum -a 256 -c && bash ~/Downloads/<ファイル名>
   ```
   成功したときに表示される内容（「■ 完了しました」）と、その後に確かめてほしい動作を具体的に書く。元に戻す方法（表示される `rollback.sh`）も添える。

## 守ること
- ファイルの受け渡し先（Google Drive など）へのアップロード・共有設定の変更・古いファイルの削除は、ユーザーの了承を得てから行う。
- 頼まれていない変更をスクリプトに混ぜない。必要そうなものは別に提案する。
- 公開リポジトリには、非公開プロジェクトのコードを含むスクリプトをコミットしない。
