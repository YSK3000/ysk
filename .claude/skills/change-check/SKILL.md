# /change-check

依頼内容: $ARGUMENTS
（空なら、この会話でユーザーが頼んだ内容を原文に近い形で書き出す）

## 手順
1. 変更内容を集める：`git status`、`git diff`、`git diff --cached`、作成したファイル、実行した/する予定のコマンド（削除や移動を含む）。
2. 次の確認を**並列で**行う（それぞれに依頼内容と変更内容を渡す）：
   - `scope-guardian` エージェント：頼まれたこと / それ以外に変わること の洗い出し（必須）
   - 組み込みの `/code-review` スキル：バグ・エッジケース（コードがある場合）。リアルタイム音声のスレッド規則、Intel / Apple Silicon の違いなど、このプロジェクト特有の注意点も伝える
   - `security-auditor` エージェント：秘密情報・公開範囲・配布スクリプト・依存の出所（スクリプト、設定、push 前は必須）。コードの脆弱性は組み込みの `/security-review` スキル
   - `numbers-verifier` エージェント：数値・ベンチマーク・計算を含む場合
   - `test-engineer` エージェント：テストがある場合は実行、実機確認が必要なら手動確認リスト
   - **画面や見た目に関わる変更があれば必須**：`design-qa`（仕様どおりか）、`accessibility-auditor`（コントラスト・大きさ・読み上げ）、`ui-ux-reviewer`（分かりやすさ・言葉）
3. 🔴（必ず直す）の指摘は直してから、もう一度該当の確認を行う。
4. 次の形でユーザーに報告する：
   - **頼まれたこと**：何をどう変えたか
   - **それ以外に変わること**：なければ「なし」と明記。あれば**適用・配布の前にOKをもらう**
   - **確認したこと**：実行したコマンドと結果
   - **確認できていないこと**：理由と、ユーザーが確かめる方法
   - **ユーザーにやってもらうこと**（あれば、コピーしてそのまま使える形）
