# サブエージェント一覧（30体）

`.claude/agents/` に置いた専門のサブエージェント。Claude が内容に応じて自動で選ぶほか、`@agent-<名前>` や「〇〇エージェントで」と指定して呼び出せる。

- **モデル**：「会話と同じ」は呼び出し元のモデルを引き継ぐ。情報集めが中心の担当は Sonnet にして、使用量を抑えている（ファクトチェックなど判断が重要な担当は会話と同じモデル）。
- **権限**：検証・計画の担当はファイルを変更できない（読み取り専用）。どの担当も、さらに別のサブエージェントを起動することはできない（無駄な連鎖を防ぐため）。

## 調査（7）

| 名前 | いつ使うか | モデル | 権限 |
|---|---|---|---|
| `docs-researcher` | ライブラリ・フレームワーク・API・OS機能の公式ドキュメント調査担当。「この関数の正しい使い方」「このAPIはどのOS/バージョンから使える？」「Appleのドキュメントで確認して」など、実装前の仕様確認に使う。Context7 MCPと公式サイトを使い、バージョンつきで答える。 | Sonnet | 読み取り専用 |
| `news-researcher` | ニュース・時事・最新動向の調査担当。「最近〜が問題になってる？」「〜の件の流れを教えて」「今どうなってる？」など、日付が大事な出来事を時系列で整理するときに使う。報道・公式発表・続報を突き合わせ、確定した情報と未確定の情報を分ける。 | Sonnet | メモ・文書の保存のみ |
| `research-synthesizer` | Web調査メモの統合担当。web-researcher・news-researcher などが集めた複数の調査メモを読み、結論・根拠・食い違い・未確認事項を整理した日本語レポートにまとめる。インタビューやアンケートなどユーザー調査の統合は design:research-synthesis スキル、/anthropic-skills:deep-research 実行中はそのスキル内の手順を使う。 | 会話と同じ | メモ・文書の保存のみ |
| `security-researcher` | 情報セキュリティの調査担当。脆弱性（CVE）、攻撃手口、情報漏えい事案、公的機関の注意喚起（JPCERT/CC・IPA・JVN・NVD・CISAなど）、個人や小さなチームが取るべき対策を調べるときに使う。手元のコードや設定の審査には security-auditor を使う。 | 会話と同じ | 読み取り専用 |
| `tech-comparator` | 製品・ツール・ライブラリ・サービスの比較担当。「AとBどっちがいい？」「〜の選択肢を比べて」など、選定・購入・導入の判断材料を作るときに使う。評価軸、価格、ライセンス、対応環境、リスクを表にまとめ、推奨を1つ示す。 | Sonnet | 読み取り専用 |
| `uncertainty-analyst` | 不確定要素の分析担当。イベントの集客人数、スケジュールや作業時間、天候、価格や市場の動き、人の行動（途中で辞める・意見を変える）、実機でしか分からない不具合など「やってみないと分からない」ことを、シナリオ・数値の幅・見るべき兆し・備えに分解するときに使う。 | 会話と同じ | 読み取り専用 |
| `web-researcher` | Web調査担当（一般）。「調べて」「〜について知りたい」「比較の材料を集めて」など、ネット上の情報収集に使い、一次情報を優先して出典URLと日付つきの調査メモを返す。日付が重要な時事は news-researcher、APIやライブラリの仕様は docs-researcher、脆弱性や漏えい事案は security-researcher を使う。 | Sonnet | メモ・文書の保存のみ |

## 検証（5）

| 名前 | いつ使うか | モデル | 権限 |
|---|---|---|---|
| `fact-checker` | ファクトチェック担当。回答・レポート・文章に含まれる事実の主張を1つずつ一次情報で検証し、「正しい／一部正しい／誤り／確認できず」で判定する。調査結果や事実を含む回答をユーザーに渡す前に積極的に使う（use proactively）。 | 会話と同じ | 読み取り専用 |
| `numbers-verifier` | 数値・計算の検算担当。表の倍率・割合・合計・平均・単位換算・日付の計算・ベンチマーク結果・見積もり金額など、数字を含む結果を出す前に使う（use proactively）。暗算せず、Pythonなどで実際に計算し直して食い違いを指摘する。 | 会話と同じ | 読み取り専用 |
| `red-team-reviewer` | 反証・批判的レビュー担当。結論・推測・計画・設計に対して「本当にそう言えるか」「見落としはないか」「逆の証拠はないか」を洗い出す。重要な判断や推測を含む回答を出す前、計画や設計を確定する前に使う。 | 会話と同じ | 読み取り専用 |
| `scope-guardian` | 変更範囲の番人。ユーザーの依頼と実際の変更（diff・削除・設定変更・動作や見た目の変化）を突き合わせ、「頼まれたこと」と「それ以外に変わること」をすべて洗い出す。コード変更・ファイル削除・設定変更をユーザーに渡す前に必ず使う（use proactively）。バグの有無の確認は組み込みの /code-review スキルの役割。 | 会話と同じ | 読み取り専用 |
| `security-auditor` | 公開・配布前のセキュリティ監査担当。秘密情報や個人情報・非公開コードの混入、公開範囲、配布スクリプトの危険なコマンド、権限の過剰、依存パッケージやMCPの出所、外部へのデータ送信を確認する。公開リポジトリへのpush前、スクリプトを配る前、パッケージやMCPを追加するときに使う。コードの脆弱性そのもののレビューは組み込みの /security-review スキルを使う。 | 会話と同じ | 読み取り専用 |

## 計画（2）

## デバッグ（3）

| 名前 | いつ使うか | モデル | 権限 |
|---|---|---|---|
| `crash-analyzer` | クラッシュ・ログ解析担当。macOS のクラッシュレポート（.ips）、スタックトレース、Console や `log show` の出力、例外メッセージ、フリーズの報告を読み解き、原因の箇所と確度を特定する。原因が分かった後の修正と再確認は debugger に渡す。 | 会話と同じ | 編集可 |

## 重複の整理

組み込みの機能・インストール済みのスキルと役割が重なるものは作らず、そちらを使う。

| 重なっていたもの | 対応 |
|---|---|
| 自作の `/deep-research` と同期済みの `/anthropic-skills:deep-research` | 自作版を削除。公式版を使い、終わった後に `fact-checker` で検証するルールを `CLAUDE.md` に置いた |
| `codebase-investigator` と組み込みの `Explore` | 削除。コードの場所探しは `Explore` |
| `solution-architect` と組み込みの `Plan` | 削除。実装方針の設計は `Plan`、段取りと見積もりは `task-planner` |
| `code-reviewer` と組み込みの `/code-review` | 削除。バグのレビューは `/code-review`。依頼外の変更の洗い出しは `scope-guardian` |
| `build-fixer` と `debugger` | `debugger` に統合（ビルド・CIの失敗も担当） |
| `security-auditor` と組み込みの `/security-review` | 役割を分けた。コードの脆弱性は `/security-review`、秘密情報・公開範囲・配布物・依存の出所は `security-auditor` |
| デザインのレビュー系と `design:*` スキル | エージェントは担当の切り分けのみ。手順は `design:design-critique`・`design:accessibility-review`・`design:design-system`・`design:design-handoff`・`design:ux-copy` があればそれに従う |
| `research-synthesizer` と `design:research-synthesis` | 対象を分けた。Web調査メモは前者、インタビュー等のユーザー調査は後者 |
| `docs-writer` と `docs` スキル（Claude Docs） | 対象を分けた。リポジトリのファイルは前者、共同編集のドキュメントは後者 |
| `requirements-analyst` と `product-management:write-spec` | 対象を分けた。依頼の整理は前者、正式な仕様書（PRD）は後者 |

## スキル（`/名前` で呼び出し）

| スキル | 内容 |
|---|---|
| `/full-cycle` | 調査 → 整理 → 設計 → デザイン → 実装 → デバッグ → 確認 → 報告 を担当に分けて通しで進める（ユーザーが呼ぶときだけ動く） |
| `/change-check` | 変更を渡す前の総点検。頼まれたこと / それ以外に変わること / 確認したこと / 確認できていないこと |
| `/fact-check` | 事実の検証表と修正案 |
| `/scenario` | 不確かなことを、シナリオ・数値の幅・見るべき兆し・備えに整理 |
| `/handoff` | 別のセッションに渡す引き継ぎメモ |
| `/mac-update-script` | Macに変更を当てる安全な更新スクリプト（チェックサム・バックアップ・試し実行・元に戻す手順） |
| `/contrast-check` | WCAG 2.2 のコントラスト比を計算して判定 |
| `/anthropic-skills:deep-research` | （同期済み）複数の調査員による本格的な調査レポート |
